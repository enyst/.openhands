# MVP

Ship in a weekend. Not a month, not a quarter. A weekend.

## When to use

You have a validated idea and pre-sold customers. Time to build the smallest thing that works.

## The principle

The MVP is not a crappy version of your vision. It's the smallest thing that delivers the core value. Manual processes, no-code tools, a spreadsheet, a landing page with a form — all valid. The goal is to get the solution into someone's hands, not to build software.

## How to apply

1. **Write down the one job your product does.** One sentence. "It helps [person] do [thing] by [how]."

2. **List everything you think it needs.** Features, pages, integrations, auth, payments, analytics...

3. **Cross out everything except the core.** If a feature doesn't directly deliver the one job, it's not in the MVP. Auth? Use a password in a DM. Payments? Use Stripe payment links or Venmo. Analytics? Count manually. Beautiful UI? A Google Form is fine.

4. **Pick the fastest path to "it works":**
   - Can you do it manually? (Concierge MVP — you are the product)
   - Can you glue existing tools together? (Zapier, Airtable, Notion, Google Sheets)
   - Can you build it in a weekend with an AI agent? (Cursor, Claude, SmolPaws)

5. **Ship it.** Give it to your pre-sold customers. Watch them use it. Take notes.

## Output

- A working thing (not a plan, not a mockup — a thing someone can use)
- Delivered to at least one real customer
- A list of what worked and what didn't from watching them use it

## Anti-patterns

- Spending weeks on infrastructure before any user touches it
- Building auth, payments, and onboarding before validating the core experience
- "I just need one more feature before I can launch"
- Perfecting the UI when nobody's seen the product yet
